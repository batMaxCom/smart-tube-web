# SmartTube for WEB — поэтапный план работ

> Цель: полноценный веб-клиент YouTube с TV-интерфейсом в духе SmartTube,
> работающий на ТВ (включая Samsung/LG/Roku/Apple TV через браузер), ПК и проекторах.

Исходник — Android-приложение SmartTube (~90k+ строк Java). **Это не порт, а полный rewrite**:
переиспользуем только продуктовую логику как «референс» (контроллеры, список фич, поведение).

---

## Архитектурное решение

```
SmartTube for WEB/
├── apps/
│   ├── web/          # Frontend: SPA, TV-first UI (React + Vite + TS)
│   └── server/       # Backend-прокси: Fastify + youtubei.js (innertube)
├── packages/
│   └── shared/       # Типы, DTO, константы, TV-навигация
├── deploy/           # Docker compose, nginx, https (Caddy)
└── tools/            # Скрипты: извлечение строк, парсинг, миграции
```

### Стек

| Слой           | Выбор                                                   | Зачем                                                    |
| -------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| Frontend       | React 19 + Vite + TypeScript + Tailwind + Zustand       | Экосистема, D-pad/фокус-библиотеки, ускорение разработки |
| Плеер          | **Shaka Player** (DASH+MSE+EME/Widevine), hls.js фолбэк | Родной для youtube-DASH, DRM, HDR, subs                  |
| Backend        | Node.js + Fastify                                       | Работает в одной экосистеме с фронтом                    |
| YouTube-данные | **youtubei.js** (innertube API) + yt-dlp как резерв     | Подписи потоков, PO-токены, обход бот-чеков              |
| Хранилище      | SQLite (server) + IndexedDB/localStorage (web)          | История, настройки, кэш                                  |
| Деплой         | Docker compose + Caddy (авто-HTTPS)                     | Один сервер, многопользовательский доступ                |

### Почему обязателен серверный прокси

Браузер не может напрямую ходить в innertube API (CORS, заголовки, PO-токены, бот-чеки).
Всю «тяжёлую» работу с YouTube делает Node-сервер; браузера — рендер UI + воспроизведение через MSE/EME.

## Непереносимое (осознанные компромиссы)

- Auto Frame Rate (подстройка герцовки ТВ) — браузер не управляет рефрешем
- Ручной выбор кодека/«высокий буфер» на уровне железа
- Системный голосовой поиск через bridge-приложение Android
- Режим «всегда на» без троттлинга вкладки

## Риски и их контрмеры

| Риск                                              | Контрмеры                                           |
| ------------------------------------------------- | --------------------------------------------------- |
| Google закрывает innertube/PO-токены              | youtubei.js + yt-dlp резерв; абстракция экстрактора |
| Блокировка по IP/ботам                            | Автовая подпись, ротация, fallback на HLS-прокладку |
| Widevine не даёт >1080p на некоторых браузерах    | hls.js + прокси подписей; честное сообщение в UI    |
| Playwright-тесты не применимы к «живому» контенту | Мок-фикстуры innertube-ответов                      |
